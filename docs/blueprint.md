# ssg-agent 쇼츠 자동화 설계도 (v0.3)

> 목적: 끝까지 가서 "이 방향이 아니었네"가 나오지 않도록, **바꾸기 어려운 것은 지금 정하고, 바꾸기 쉬운 것은 나중에 바꿀 수 있게** 설계한다.
> 이 문서는 계속 고쳐 쓰는 문서다. 결정이 바뀌면 맨 아래 "결정 기록"에 남긴다.

---

## 0. 큰 그림

```
[관리자 화면]  ─ 보기/승인/수정/재시도 ─┐
                                          ▼
[감독: Claude] ── 단계 순서 결정, 검수, 타임라인 작성
      │
      ├─ 역할 슬롯(바꿔 끼우기 가능)
      │    분석 · 기획 · 대본 · 이미지 · 영상클립 · 음성 · 음악 · 효과음 · 자막 · 검수
      │
      ▼
[프로젝트 기록]  ← 모든 단계의 입력/출력/상태/비용 저장 (Supabase + 로컬 폴더)
      │
      ▼
[조립기: ffmpeg]  → mp4 → (선택) 업로드 → 성과 수집 → 다음 기획에 반영
```

**핵심 원칙 5가지**

1. **기록이 중심이다.** 화면·알림·재시도·비용은 전부 "프로젝트 기록"을 읽고 쓴다. 엔진과 화면은 서로를 몰라도 된다.
2. **AI는 역할 슬롯에 꽂는 부품이다.** 코드는 "이미지 만들어줘"만 알고, 그게 GPT인지 Flux인지는 설정이 정한다.
3. **단계는 다시 돌릴 수 있어야 한다.** 각 단계는 앞 단계 결과만 보고 동작한다 → 실패한 단계·마음에 안 드는 장면만 재생성.
4. **사람이 끼어들 자리를 처음부터 만든다.** 모든 단계에 "자동 통과 / 승인 대기" 스위치.
5. **편집의 최종 결과물은 "타임라인(JSON)"이다.** mp4는 타임라인을 렌더링한 결과일 뿐. 타임라인만 있으면 언제든 다시 렌더링·수정 가능.

## 1. 바꾸기 어려운 것 vs 쉬운 것

| 지금 꼭 정해야 함 (나중에 바꾸면 대공사) | 나중에 바꿔도 됨 (설정만 바꾸면 됨) |
|---|---|
| 프로젝트/단계 데이터 구조 (2장) | 어떤 AI 모델을 쓸지 (5장) |
| 타임라인 형식 (4장) | 프롬프트 문구 |
| 파일 저장 위치·이름 규칙 (6장) | 화면 디자인, Streamlit → 웹앱 전환 |
| 역할 슬롯 목록과 어댑터 규칙 (5장) | 알림 수단 (텔레그램/카톡) |
| 단계 상태 값 (대기/실행/승인대기/완료/실패) | 화면비율·길이 기본값 |

→ 그래서 **구현 1순위는 왼쪽 열**이다.

## 2. 데이터 구조 (프로젝트 기록)

**맨 위 구조 (여러 채널 + 나중에 팀원)** — 지금은 혼자 쓰더라도 처음부터 이 모양으로 만든다. 나중에 끼워 넣으면 모든 기록을 옮겨야 해서 대공사가 된다.

```
Workspace (작업공간: 나 또는 우리 팀)
├── Members[]     구성원 + 권한 (소유자 / 편집자 / 승인자 / 보기만)
├── Providers     AI 연결 설정·키 (작업공간 단위로 공유)
├── Library       공용 라이브러리 (효과음·BGM·프롬프트·장르 템플릿)
└── Channels[]    운영 채널 (예: 신앙 채널, 책 채널, 정보 채널)
      ├── Brand          로고, 폰트, 색, 인트로/아웃트로
      ├── Defaults       기본 장르, 그림체, 목소리, 규격, 자동화 수준, 예산
      ├── Library        채널 전용 캐릭터·스타일 프리셋
      ├── UploadAccounts 연결된 유튜브/틱톡/인스타 계정
      └── Projects[]     이 채널의 영상들 ↓
```

- 모든 기록에 `workspace_id`, `channel_id`, `created_by`, `updated_by`를 처음부터 넣는다
- 1차 구현은 로그인 없이 "작업공간 1개 + 나 1명"으로 동작하되 구조는 위와 같게

```
Project (영상 1편)
├── Spec          출력 규격 (비율, 길이, 해상도, 언어, 플랫폼…)  → 3장
├── Brief         주제, 선택된 핵심 지침, 타깃 시청자, 금지사항
├── Uploads[]     내가 올린 자료 (2-1 참고: 참고 영상·이미지, 캐릭터, 소품, 녹음, 음악…)
├── References[]  참고 영상(링크 또는 파일) + 분석 결과(StyleCard)
├── Cast[]        이 영상에 나오는 캐릭터 (Character 라이브러리에서 연결)
├── Script        대본 (훅 / 본문 / CTA), 대사 줄마다 화자·감정·속도
├── Scenes[]      장면(샷) 목록
│     └── Scene: 길이, 대사, 화면설명, 앵글, 카메라움직임, 전환, 효과음 큐
│           └── Assets[]: 이미지/영상클립/음성 (버전별 보관, 채택본 표시)
├── AudioPlan     BGM, 전체 음량 규칙
├── Timeline      최종 편집 설계도 (4장)
├── Renders[]     렌더 결과 mp4 (버전)
├── Publish       제목, 설명, 해시태그, 썸네일, 업로드 예약/결과
└── Metrics       조회수·시청지속률 등 (업로드 후 수집)

Run (실행 1회) ─ Steps[]
└── Step: 단계명, 상태, 사용한 AI/모델, 입력, 출력, 소요시간, 비용, 에러메시지, 재시도 횟수
```

### 2-1. 올릴 수 있는 자료 (업로드)

모든 업로드는 **용도 태그**를 붙여 저장한다. 용도에 따라 어느 단계가 그 자료를 쓰는지가 정해진다.

| 용도 태그 | 예시 | 형식 | 쓰는 단계 |
|---|---|---|---|
| `ref_video` 참고 영상 | 따라 하고 싶은 쇼츠 | 유튜브 링크 / mp4·mov 파일 | 3 스타일 분석 |
| `ref_image` 참고 이미지 | 원하는 그림체, 색감, 구도 캡처 | png·jpg·webp | 3 스타일 분석, 8 장면 이미지(참조) |
| `character` 캐릭터 | 다른 곳에서 만든 캐릭터 | 이미지 1장 이상 | 4 캐릭터 준비 (→ 시트 확장) |
| `prop` 소품 / `background` 배경 | 제품 사진, 책 표지, 장소 사진 | 이미지 | 8 장면 이미지(참조/합성) |
| `scene_asset` 완성 장면 | 직접 만든 이미지·영상 클립 | 이미지 / mp4 | 8 (해당 장면에 그대로 사용) |
| `voice` 내 녹음 | 대사 녹음 | mp3·wav·m4a | 6 음성 |
| `music` / `sfx` | 직접 고른 BGM·효과음 | mp3·wav | 9 소리 배치 (라이브러리로 등록 가능) |
| `brand` | 로고, 폰트, 인트로 영상 | png·ttf·mp4 | 채널 브랜드 |
| `doc` 문서 | 책 메모, 대본 초안, 설교 요약 | txt·md·pdf | 2 기획, 5 대본 |

- 업로드 위치: 프로젝트 전용(이 영상에서만) 또는 라이브러리(채널/작업공간에서 재사용) 중 선택
- 업로드할 때 **권리 확인 체크**: "내가 만들었거나 사용 권한이 있음"을 표시하지 않으면 렌더링 전에 경고
- 참고 영상·참고 이미지는 **분석에만** 쓰고, 그 화면 자체를 결과물에 넣지 않는다 (`scene_asset`만 결과물에 직접 들어감)

**재사용 라이브러리** (프로젝트 밖에 따로 보관, 여러 영상에서 씀)

- `Character` — 캐릭터 설정화(정면/측면/뒷모습/표정 시트), 성격, 말투, 지정 목소리, 업로드/생성 출처
- `StylePreset` — 분석해서 저장한 스타일 카드 ("A채널 스타일", "빠른 정보형"…)
- `VoicePreset` — 음성 AI + 목소리 + 속도/톤
- `SfxLibrary` — 효과음 파일 + 태그 (휙, 뿅, 띵, 쾅, 타자, 박수…)
- `BgmLibrary` — 음원 + 분위기/BPM/길이/라이선스 출처
- `PromptTemplate` — 단계별 지시문 (버전 관리)
- `Brand` — 채널 로고, 폰트, 색상, 고정 인트로/아웃트로, 워터마크

**단계 상태 값 (고정)**: `pending` 대기 → `running` 실행 중 → `awaiting_approval` 승인 대기 → `done` 완료 / `failed` 실패 / `skipped` 건너뜀

## 3. 출력 규격 (Spec) — 영상마다 정하는 기본 설정

| 항목 | 선택지 | 기본값 | 메모 |
|---|---|---|---|
| 화면 비율 | 9:16 / 1:1 / 4:5 / 16:9 | **9:16** | 쇼츠·릴스·틱톡 공통 |
| 해상도 | 720p / 1080p / 4K | **1080×1920** | |
| 프레임 | 24 / 30 / 60 fps | **30** | 애니풍은 24도 좋음 |
| 길이 | 15 / 30 / 45 / 60 / 90초 / 직접 | **30~45초** | 유튜브 쇼츠 최대 3분. 짧을수록 완주율↑ |
| 언어 | 한국어 / 영어 / 다국어 | 한국어 | 다국어면 같은 영상의 자막·음성만 교체 |
| 대상 플랫폼 | 유튜브 / 틱톡 / 인스타 | 유튜브 | 플랫폼별 안전영역·제목 길이 다름 |
| 장르 | 신앙 / 자기계발 / 책이야기 / 정보형 / 스토리 / 밈·유머 / 제품소개 | 채널 기본값 | 장르마다 **장르 템플릿**(3-1)이 구조·톤·길이를 정함 |
| 그림체 | 3D 캐릭터 / 2D 애니 / 실사풍 / 수채화·일러스트 / 텍스트·타이포 중심 | **기본값 없음, 매번 선택** | 채널 기본값으로 저장 가능 |
| 화면 구성 방식 | 정지이미지+움직임 / AI영상클립 / 섞기 | **정지이미지+움직임** (+핵심 장면 1~2개만 AI 클립 선택) | 비용 차이 큼 |
| 목소리 | AI 목소리 / 내 녹음 업로드 / 장면별 섞기 | 채널 기본값 | 3-2 참고 |
| 자막 | 없음 / 문장 / 단어별 강조(카라오케) | 단어별 강조 | |
| 품질/예산 등급 | 연습 / 보통 / 고급 | **보통** | 등급별로 모델·품질 자동 선택 |
| 자동화 수준 | 7-1 참고 | 레벨 1 | 채널 기본값 + 프로젝트별 변경 |

### 3-1. 장르 템플릿 (우선 만들 7종)

장르마다 기본 구조·톤·길이·그림·소리를 묶어 둔 것. 주제를 넣으면 이 템플릿을 바탕으로 핵심 지침 후보를 만든다. 화면에서 수정·추가 가능.

| 장르 | 기본 길이 | 구조 | 톤·목소리 | 화면 | BGM 분위기 | 특별 주의 |
|---|---|---|---|---|---|---|
| **신앙** | 30~60초 | 공감 질문 → 말씀/메시지 → 적용 → 축복·기도 | 따뜻하고 차분, 느린 속도 | 빛·자연·인물 뒷모습, 말씀 구절 타이포 | 잔잔한 피아노·현악 | 번역본 **개역개정**(3-3 참고). 교단·교리 표현 검수 |
| **자기계발** | 30~45초 | 강한 훅(문제 제기) → 원인 → 해결 3가지 → 한 줄 정리 | 단호·확신, 약간 빠름 | 인물·상황 연출, 큰 키워드 자막 | 긴장감→희망 상승 | 과장·허위 효과 주장 금지 |
| **책이야기** | 45~90초 | 책 속 한 문장/질문 훅 → 핵심 메시지 → 내 이야기/적용 → 책 소개 | 낭독·내레이션, 감성 | 장면 일러스트 + 인용문 타이포, 책 표지(조건부) | 감성 피아노·로파이 | **인용은 짧게, 출처 표기**, 책 내용 요약은 저작권 범위 주의, 표지 이미지 사용 기준 확인 |
| **정보형** | 30~45초 | 훅(놀라운 사실) → 핵심 3개 → 요약·CTA | 밝고 빠름 | 아이콘·도표·예시 장면 | 경쾌 | 사실 확인 필요 항목 자동 표시 |
| **스토리** | 45~90초 | 상황 → 갈등 → 반전 → 여운/웃음 | 캐릭터별 목소리, 대화체 | 캐릭터 중심, 표정 변화 | 장면별 전환 | 캐릭터 일관성 최우선 |
| **밈·유머** | 15~30초 | 상황 제시 → 빵 터지는 한 방 → (반복/후속) | 과장, 리액션 | 리액션 표정, 빠른 컷 | 효과음 위주 | 실존 인물·타 저작물 밈 원본 사용 금지 |
| **제품소개** | 30~45초 | 불편 제기 → 제품 등장 → 기능 3개 → 가격·혜택 → CTA | 친근·확신 | 제품 화면·사용 장면 | 업템포 | 광고 표시(유료 광고 포함), 과장 광고 금지 |

> 참고 채널(예: 이혜성, 하와이대저택 같은 책·자기계발 채널)은 **스타일 카드 분석 대상**으로만 쓴다. 구조·리듬·톤은 참고하되 대사·화면·브랜드는 새로 만든다.

### 3-2. 목소리 방식

- **AI 목소리**: 캐릭터/채널마다 VoicePreset 지정
- **내 녹음 업로드**: 대본을 "녹음용 대본"(줄 번호 + 읽는 속도·감정 표시)으로 내려받아 녹음 → 줄별 파일 또는 통파일 업로드 → 자동으로 줄 나누기·자막 시간 맞추기
- **섞기**: 내레이션은 내 목소리, 캐릭터 대사는 AI 목소리처럼 장면·화자별로 지정
- 녹음 파일도 AI 음성과 똑같이 음량 맞추기·잡음 제거를 거친다
- (나중) 내 목소리를 AI로 복제하는 것은 별도 결정 — 본인 동의·서비스 약관 확인 후

### 3-3. 성경 본문 (신앙 장르)

- 기본 번역본: **개역개정** (대한성서공회 저작권)
- 저작권 규칙: 인용은 **짧은 구절 단위**로, 영상 설명란에 출처 표기 — 예: `성경 본문: 개역개정판 ⓒ 대한성서공회`
- 수익 채널에서 쓰기 전에 대한성서공회의 **인용 허락 범위를 한 번 확인**하고 결과를 결정 기록에 남긴다 (몇 절까지, 출처 표기 방식)
- 대본 단계에서 구절은 `책 장:절` 참조로만 저장하고, 본문은 사용자가 확인한 출처에서 넣는다 → AI가 구절을 틀리게 지어내는 것 방지
- 구절 자막은 별도 스타일(말씀 타이포)로 표시

**안전영역(Safe zone)**: 쇼츠는 아래쪽 약 20%(제목·설명), 오른쪽 세로줄(좋아요·댓글 버튼)이 UI에 가려진다. 자막·핵심 그림은 화면 가운데~위쪽 2/3에 둔다. → 조립기가 플랫폼별 안전영역을 자동 적용.

## 4. 타임라인 형식 (최종 편집 설계도)

모든 편집 결정은 이 JSON 하나에 담긴다. Claude가 작성하고, 사람은 화면에서 고치고, ffmpeg가 렌더링한다.

```json
{
  "spec": { "aspect": "9:16", "width": 1080, "height": 1920, "fps": 30 },
  "tracks": {
    "video": [
      { "scene": 1, "start": 0.0, "end": 2.4, "asset": "scenes/01/img_v2.png",
        "motion": "zoom_in_slow", "transition_in": "cut" }
    ],
    "voice":   [ { "start": 0.2, "asset": "audio/line01.mp3", "speaker": "char_mimi" } ],
    "captions":[ { "start": 0.2, "end": 1.8, "text": "이거 모르면 손해", "style": "hook_big",
                   "words": [ { "w": "이거", "t": 0.2 }, { "w": "모르면", "t": 0.6 } ] } ],
    "sfx":     [ { "at": 0.0, "asset": "sfx/whoosh.wav", "volume": 0.8 } ],
    "bgm":     [ { "start": 0.0, "asset": "bgm/upbeat_01.mp3", "volume": 0.25, "duck_under_voice": true } ],
    "overlays":[ { "start": 0, "end": 30, "asset": "brand/logo.png", "position": "top_left" } ]
  }
}
```

- `motion`(움직임) 목록: 정지, 천천히 줌인/줌아웃, 좌우/상하 패닝, 흔들림(강조), 펀치인(순간 확대)
- `transition`(전환) 목록: 컷, 휙(whip), 페이드, 줌 전환, 글리치
- `caption style` 목록: 훅(크게), 기본, 강조어 색상, 말풍선, 화자별 색
- **음량 규칙**: 목소리 나올 때 BGM 자동으로 낮추기(덕킹), 최종 음량 약 -14 LUFS(유튜브 기준)

## 5. 역할 슬롯과 선택 가능한 AI

### 5-1. 역할 목록 (고정)

| 역할 | 하는 일 | 기본 담당 | 바꿔 끼울 수 있는 후보 (예시, 시기마다 바뀜) |
|---|---|---|---|
| **감독** | 순서 결정, 검수, 타임라인 작성 | Claude | — |
| **영상 분석** | 참고 영상 → 스타일 카드 | Gemini | (영상 직접 이해는 Gemini가 독보적) |
| **기획** | 주제 → 핵심 지침 후보 3~5개 | Claude | Gemini, GPT |
| **대본** | 지침+스타일 → 대본·장면 콘티 | Gemini | Claude, GPT |
| **캐릭터 생성** | 설정화·표정 시트 | GPT 이미지 | Gemini 이미지(Nano Banana 계열), Flux, 업로드 |
| **장면 이미지** | 장면별 그림 (캐릭터 참조 유지) | GPT 이미지 | Gemini 이미지, Flux, Ideogram(글자 많은 그림) |
| **영상 클립** | 이미지→움직이는 영상 | 없음(움직임 효과로 대체) | Veo, Sora, Kling, Runway, Hailuo, Seedance |
| **음성(TTS)** | 대사 읽기 | GPT TTS | ElevenLabs, Gemini TTS, Typecast·클로바(한국어 특화) |
| **립싱크** | 캐릭터 입 모양 맞추기 | 없음 | 영상 AI 일부 지원, 전용 립싱크 서비스 |
| **음악(BGM)** | 배경음악 | 라이브러리에서 고르기 | Lyria, ElevenLabs Music |
| **효과음** | 큐 위치에 효과음 | 라이브러리에서 고르기 | ElevenLabs SFX (라이브러리에 없을 때만 생성 → 라이브러리에 추가) |
| **자막 시간** | 음성 → 단어별 시간 | Whisper 계열 | Gemini, ElevenLabs STT |
| **검수(QA)** | 완성 영상 보고 문제 지적 | Gemini | — |
| **메타데이터** | 제목·설명·해시태그·썸네일 문구 | Claude | GPT, Gemini |

> 공식 API가 없는 서비스(예: Midjourney, Suno)는 자동화에 넣지 않는다. 쓰고 싶으면 **"직접 만들어서 업로드"** 슬롯으로 처리 — 모든 이미지/음성/음악 슬롯은 "업로드"를 선택지로 항상 가진다.

### 5-2. 어댑터 규칙 (새 AI 붙이는 방법)

- 역할마다 공통 함수 모양을 정한다. 예: `image.generate(prompt, size, reference_images) → 파일경로`
- AI마다 어댑터 파일 1개: `providers/image/gpt.py`, `providers/image/flux.py` …
- 어댑터는 **자기 능력표**를 같이 낸다 → 화면이 선택 가능한 옵션을 자동으로 보여줌

```yaml
# 능력표 예시
id: video.kling
role: video_clip
needs_key: KLING_API_KEY
aspects: ["9:16", "16:9", "1:1"]
max_seconds: 10
supports_reference_image: true
supports_audio: false
cost_per_second_usd: 0.07   # 대략, 비용 추정용
```

- 모델 선택 우선순위: **프로젝트 지정 > 품질등급 기본값 > 전역 기본값 > 예비 모델**
- 실패 시: 같은 모델 재시도(대기) → 예비 모델 → 그래도 실패면 단계 `failed` + 알림 (지금 `gemini_video.py`의 방식을 전 역할로 확장)

### 5-3. "힉스필드 메뉴"가 되지 않게

모델 고르는 메뉴가 끝없이 늘어나면 쓰기 어려워진다. 그래서:
- 평소 화면에는 **품질등급(연습/보통/고급)** 하나만 보인다 → 등급이 모델을 정함
- 모델을 직접 고르는 건 **고급 설정**에 숨긴다
- 차이점: 힉스필드류는 "한 장 한 장 만드는 도구", 우리는 **"프로젝트 기록 + 타임라인이 있는 제작 파이프라인"**. 메뉴가 아니라 흐름이 중심.

## 6. 파일 저장 규칙

```
templates/                         ← 기본 템플릿 (git에 포함)
  genres/  faith.json, self_help.json, book.json …
workspace/                         ← 실제 작업 데이터 (git 제외, 나중에 Supabase와 동기화)
  workspace.json                   작업공간 정보, 구성원, 설정
  library/                         작업공간 공용: sfx/ bgm/ prompts/ genres/
  channels/
    book/                          채널 슬러그
      channel.json                 브랜드·기본값·유튜브 설정 체크리스트
      library/                     채널 전용: characters/ styles/ voices/ brand/
      projects/
        20261119_p0001_잠잘때손해보는습관/
          project.json             ← 2장의 기록
          uploads/                 내가 올린 자료 (2-1)
          refs/                    참고 영상 분석 결과
          cast/                    이 영상용 캐릭터 이미지 사본
          scenes/01/               img_v1.png, img_v2.png(채택), clip_v1.mp4
          audio/                   line01.mp3 …, bgm, 믹스 결과
          timeline.json
          renders/                 v1.mp4, v2.mp4
          publish/                 thumbnail.png, meta.json
```

- 프로젝트 번호(`p0001`)는 작업공간 전체에서 하나씩 증가 → 채널이 달라도 겹치지 않음

- 파일은 **덮어쓰지 않고 버전 번호**를 붙인다 (`_v1`, `_v2`), 채택본은 기록에 표시
- 큰 파일(영상)은 로컬, 화면/폰에서 볼 미리보기·썸네일은 Supabase Storage에
- **정리 정책**: 완료 후 30일 지난 미채택 버전은 정리 대상으로 표시 (자동 삭제 X, 확인 후 삭제)

## 7. 제작 흐름 (단계 순서)

| # | 단계 | 입력 | 출력 | 기본 승인 |
|---|---|---|---|---|
| 1 | 규격 정하기 | 사용자 | Spec | 사용자 입력 |
| 2 | 기획: 핵심 지침 후보 | 주제 | 지침 3~5개 | **선택/수정/직접입력** |
| 3 | 참고 영상 분석 (선택) | 링크 | StyleCard | 확인 |
| 4 | 캐릭터 준비 | 업로드 or 생성 요청 | Character + 표정시트 | **승인** |
| 5 | 대본 + 장면 콘티 | 지침, StyleCard, Cast, Spec | Script, Scenes | **승인** |
| 6 | 음성 생성 / 내 녹음 업로드 | Script, VoicePreset 또는 녹음 파일 | 대사 음성들 | 자동 (녹음 방식이면 업로드 대기) |
| 7 | 자막 시간 맞추기 | 음성 | 단어별 시간 | 자동 |
| 8 | 장면 이미지/클립 | Scenes, Cast | Assets | **장면별 재생성 가능** |
| 9 | 음악·효과음 배치 | AudioPlan, 큐 | 오디오 트랙 | 자동 |
| 10 | 타임라인 작성 | 전부 | timeline.json | 자동 |
| 11 | 렌더링 | timeline | mp4 | 자동 |
| 12 | 검수(QA) | mp4 | 문제 목록 | 문제 있으면 승인 대기 |
| 13 | 메타데이터·썸네일 | Script | 제목/설명/태그 | 확인 |
| 14 | 업로드 | 전부 | 업로드 결과 | 업로드 방식(7-2)에 따름 |
| 15 | 성과 수집 (나중) | 영상 ID | Metrics | 자동 |

> 음성(6)을 이미지(8)보다 먼저 하는 이유: **장면 길이는 대사 길이가 정한다.** 음성이 나와야 정확한 컷 길이가 나온다.

### 7-1. 자동화 수준 (채널 기본값, 프로젝트마다 변경 가능)

모든 단계에 개별 "자동 통과 / 승인 대기" 스위치가 있고, 아래 레벨은 그 스위치들을 한 번에 맞추는 프리셋이다.

| 레벨 | 이름 | 멈추는 단계 | 이럴 때 |
|---|---|---|---|
| 0 | 전부 확인 | 모든 단계 | 처음 써볼 때, 새 장르 |
| 1 | 기획 확인 | 지침(2), 캐릭터(4), 대본(5), 최종 검수(12) | **기본값** |
| 2 | 최종만 확인 | 최종 검수(12)만 | 템플릿이 안정된 채널 |
| 3 | 완전 자동 | 없음 (에러·예산 초과·QA 문제 시에만 멈춤) | 검증된 반복 시리즈 |
| 직접 | 사용자 지정 | 단계별로 골라서 | |

### 7-2. 업로드 방식 (채널마다 선택)

| 방식 | 동작 |
|---|---|
| **파일만** (1차 기본) | mp4 + 제목/설명/태그/썸네일을 내려받기 |
| **비공개 업로드** | 유튜브에 비공개(또는 초안)로 올려두고, 공개는 사람이 직접 |
| **예약 공개** | 승인 후 지정 시간에 자동 공개 |
| **즉시 공개** | 승인 없이 바로 공개 (레벨 3에서만 선택 가능, 경고 표시) |

- 업로드 계정은 채널마다 연결 (2장 `UploadAccounts`)
- 1차 구현은 "파일만" → M9에서 비공개 업로드 → 예약 공개 순서로 추가

## 8. 스타일 카드 (참고 영상 분석 결과)

"그 느낌 그대로"를 숫자와 목록으로 바꾼 것. Gemini가 정해진 JSON 형식으로 채운다.

- **구조**: 훅(첫 1~3초) 방식, 본문 전개, 반전/클라이맥스 위치, 마무리·CTA 방식
- **편집 리듬**: 평균 컷 길이, 컷 수, 가장 빠른/느린 구간
- **샷 목록**: 장면별 시간, 앵글(정면/로우/하이/클로즈업/전신), 카메라 움직임, 전환
- **자막**: 위치, 크기, 색, 강조 방식, 이모지 사용
- **대사 톤**: 말투(반말/존댓말), 속도, 감정, 1인칭/2인칭, 문장 길이
- **소리**: BGM 분위기·BPM, 효과음 종류와 타이밍, 무음 구간
- **비주얼**: 그림체(실사/3D/2D/픽셀…), 색감, 조명
- **따라 하지 않을 것 (자동 표시)**: 원본 대사 문장, 로고·브랜드, 고유 캐릭터, 원본 음악

> 정확도 보강: 쇼츠는 컷이 빨라서 Gemini 기본(초당 1장)으로는 리듬을 놓친다 → 분석 프레임 수를 올리고, 가능하면 컷 위치를 별도로 검출해 함께 넣는다.

## 9. 캐릭터 일관성

- 캐릭터 등록 시 **기준 시트**를 만든다: 정면·측면·뒷모습 + 표정 6종(기쁨/놀람/화남/슬픔/생각/윙크)
- 장면 이미지 생성 시 **항상 기준 시트를 참조 이미지로 같이 넣는다**
- 캐릭터마다 고정 문구(외모 설명)를 저장해 모든 프롬프트 앞에 붙인다
- 업로드 캐릭터도 같은 방식 (업로드 1장 → AI로 시트 확장 → 승인)
- 캐릭터마다 **지정 목소리**를 연결 (VoicePreset)

## 10. 관리자 화면 구성

| 화면 | 내용 |
|---|---|
| **채널 선택 (맨 위 고정)** | 작업 중인 채널 전환, "전체 채널" 보기 |
| **대시보드** | 진행 중/승인 대기/실패 프로젝트, 오늘 쓴 비용, 최근 알림 (채널별/전체) |
| **채널 설정** | 브랜드, 기본 장르·그림체·목소리·자동화 수준·업로드 방식·예산 |
| **팀원 (나중)** | 초대, 권한(소유자/편집자/승인자/보기만), 승인 알림 받을 사람 |
| **새 프로젝트** | 규격 → 주제 → 지침 선택 → 참고영상 → 캐릭터 (마법사 형태) |
| **프로젝트 상세** | 단계 진행 막대, 단계별 결과 보기·수정·재실행, 장면 갤러리, 미리보기 |
| **타임라인 편집 (나중)** | 장면 길이·자막·효과음 위치 간단 수정 |
| **라이브러리** | 캐릭터, 스타일, 목소리, 효과음, BGM, 브랜드 |
| **AI 연결 설정** | 역할별 담당 AI, 모델, 키 상태, [연결 테스트] |
| **프롬프트 관리** | 단계별 지시문 수정, 버전 비교, 되돌리기 |
| **실행 내역** | 모든 Run/Step 로그, 에러, 비용, 사용 모델 |
| **설정** | 기본 규격, 품질등급, 하루 예산 한도, 알림 수단 |

| **유튜브 시작 도우미** | 채널별 개설·설정 체크리스트 (16장) |
| **자료 올리기** | 끌어다 놓기 업로드 + 용도 태그 선택 (2-1) |

**자동/승인 스위치**: 프로젝트마다 "완전 자동" 또는 "표시된 단계에서 멈춤"을 고른다.

**화면 톤 후보** (M6 전에 하나 고름, 색은 설정 파일 하나로 바꿀 수 있게 만든다)

- A. 미드나잇 가이드 — 지금 설치 안내서와 같은 남색 카드, 번호 단계, 주황 안내 상자
- B. 스튜디오 라이트 — 밝은 회백색, 차분한 색 배지, 낮 작업·팀 공유용
- C. 편집실 프로 — 검정 바탕, 촘촘한 정보, 단계 진행 막대, 숫자는 고정폭 글꼴

## 11. 에러·알림·비용

- **에러 표시**: 실패 단계 빨간색 + 쉬운 설명 + 원본 에러(접기) + [다시 시도] [다른 모델로 시도] [건너뛰기]
- **에러 분류**: 일시적(붐빔·시간초과 → 자동 재시도) / 설정 문제(키 없음·잔액 부족 → 즉시 알림) / 내용 문제(안전 필터 거절 → 프롬프트 수정 필요, 승인 대기)
- **알림 시점**: 승인 필요, 실패, 완료, 예산 80%/100% 도달
- **알림 수단**: 텔레그램(1순위, 쉬움) → 카톡 나에게 보내기(추가 옵션) — 알림 어댑터로 만들어 바꿔 끼우기
- **비용**: 단계마다 예상 비용(실행 전)과 실제 비용(실행 후) 기록. 하루/프로젝트 한도 넘으면 자동 정지
- **예산 기본값** (월 3~10만원 계획 기준): 작업공간 월 한도 **10만원**, 하루 한도 **7천원**, 채널별 월 한도 나눠 설정 가능. 80%에서 경고, 100%에서 정지
  - AI 영상 클립은 비용이 커서 "보통" 등급에서는 영상당 최대 1~2개로 제한
  - M2에서 실제 영상 1편 비용을 측정한 뒤 이 기본값을 다시 조정한다
- **누구에게 알림**: 1차는 나에게. 팀이 생기면 승인 요청은 "승인자", 에러는 "소유자"에게
- **키 보안**: API 키는 `.env`/비밀 저장소에만. 화면에는 "연결됨 ●"만 표시

## 16. 유튜브 시작 도우미

유튜브가 처음이어도 채널을 제대로 세팅할 수 있게, 채널마다 체크리스트를 화면에서 하나씩 진행한다. 각 항목은 "설명 + 우리 도구가 대신 만들어 주는 것 + 내가 직접 할 일"로 구성하고, 완료 여부를 `channel.json`에 저장한다.

| # | 항목 | 도구가 해 주는 것 | 내가 할 일 |
|---|---|---|---|
| 1 | 채널 만들기 | 방법 안내: 여러 채널·팀원 공유를 위해 **브랜드 계정** 채널 권장 | 유튜브에서 채널 생성 |
| 2 | 채널 이름·핸들(@) | 이름 후보 추천 (17장) | 사용 가능한 핸들 확인·등록 |
| 3 | 휴대폰 인증 | 왜 필요한지 안내 (맞춤 썸네일, 긴 영상 등) | 유튜브 스튜디오에서 인증 |
| 4 | 프로필 사진·배너 | GPT로 시안 생성, 규격 맞춤 (프로필 정사각형, 배너 안전영역) | 마음에 드는 시안 업로드 |
| 5 | 채널 설명·키워드 | Claude가 장르에 맞게 작성 | 확인 후 붙여넣기 |
| 6 | 업로드 기본 설정 | 권장값 안내: 카테고리, 언어, 기본 태그, 설명 템플릿 | 스튜디오 설정에 입력 |
| 7 | 시청자층(아동용 여부) | 장르별 판단 기준 안내 | 반드시 직접 선택 |
| 8 | AI 콘텐츠 표시 | 언제 "합성 콘텐츠" 표시가 필요한지 안내 | 업로드 시 체크 |
| 9 | 수익화 조건 | 현재 조건 확인 방법과 진행률(구독자·조회수) 표시 | — |
| 10 | 폰 앱 | 유튜브 스튜디오 앱 설치 안내 (댓글·통계 확인) | 설치 |
| 11 | 업로드 자동화 연결 (M9) | Google Cloud 프로젝트·YouTube API 연결 단계 안내 | 계정 로그인·권한 허용 |
| 12 | 팀원 권한 (나중) | 유튜브 채널 권한(관리자/편집자/뷰어) 안내 | 초대 |

> 유튜브 정책·수익화 조건은 자주 바뀌므로, 도우미는 숫자를 고정해 두지 않고 **공식 도움말 링크 + 확인 날짜**를 함께 보여준다.
